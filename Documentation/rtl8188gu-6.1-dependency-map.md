# RTL8188GU / RTL8710BU — GKID 6.1.177 dependency map

## Scope and safety boundary

Target: GKID-NH source baseline `f391d5a36ae325a4f3abdf497335abae87734a05` (Linux 6.1.177), isolated branch `rtl8188gu-backport-6.1-nh`.

Reference implementation: upstream Linux commit `70664495e3d24803ec47ccaccee9a822220558a0` (2023-03-20).

This document is an audit only. It does not modify kernel code, configuration, firmware, or packaging. The original kernel ZIP and all other branches remain out of scope.

## Confirmed baseline differences

| Area | GKID target baseline | Upstream RTL8710BU patch |
|---|---|---|
| rtl8xxxu Makefile | core + 8192e + 8723b + 8723a + 8192c | additionally links 8188f, 8188e, and new 8710b objects |
| 8188f / 8188e source files | absent from target directory | present and linked |
| Kconfig | older chip list; no LEDS_CLASS dependency | adds LEDS_CLASS dependency and RTL8710BU/RTL8188GU support text |
| shared chip enum | ends with RTL8188F | adds RTL8710B |
| shared private state | no RTL8710BU package/indirect-register state | adds package and Jaguar2/indirect-access state |
| RX/PHY status | older parser and structures | adds three Jaguar2 PHY status layouts and dispatch |
| USB matching | no 0xb711 match | adds RTL8710BU USB match and chip fileops |
| chip implementation | no 8710b subdriver | adds 1,878-line rtl8xxxu_8710b.c |

The target's missing 8188e/8188f source files are a major blocker: the upstream patch is not a self-contained new-file drop-in. Its Makefile change assumes those subdrivers already exist. Copying only the new 8710b file or blindly applying the complete patch to this older tree is not safe.

## Dependency graph and port order

1. **Freeze and fingerprint baseline**
   - Record branch HEAD, source commit, hashes of all rtl8xxxu files, and builder config.
   - Keep this isolated branch only; do not change `dev`, `GKID-6.1`, or `rtl8188gu-backport-6.1`.

2. **Establish a coherent rtl8xxxu base**
   - Determine the nearest Linux 6.1-compatible upstream rtl8xxxu revision that contains 8188e/8188f and matches this target's API era.
   - Compare all shared structures, callback signatures, register definitions, and core helpers before selecting a port base.
   - Do not replace the whole directory without a per-file regression review.

3. **Shared header and register layer**
   - Add RTL8710B chip identity, efuse layout, Jaguar2 PHY-stat structures, private-state members, and new register definitions.
   - Audit all structure layout and bitfield endianness.
   - Add indirect register access synchronization and the RTL8710BU register-window mapping. Its register map is not a simple universal +0x8000 offset; special cases and indirect accesses exist.
   - Keep existing chip accessors behavior-identical for every non-RTL8710B chip.

4. **Core firmware and power sequencing**
   - Port chip-specific firmware download/control handling, reset/power-on/power-off, efuse read/parse, and synchronization lifecycle.
   - Firmware names in upstream are `rtlwifi/rtl8710bufw_SMIC.bin` and `rtlwifi/rtl8710bufw_UMC.bin`. Do not guess the adapter's silicon variant; validate firmware licensing and package both compatible variants if appropriate.
   - Ensure failure paths release firmware, mutexes, USB resources, and allocated state.

5. **RX/TX datapath**
   - Add Jaguar2 PHY-stat parsing and dispatch without changing old RX descriptor parsing for other chips.
   - Port RTL8710BU TX descriptor checksum/format quirks and USB endpoint/aggregation behavior.
   - Validate skb bounds, alignment, endianness, and descriptor sizes.

6. **Chip subdriver**
   - Port the 8710b PHY/RF tables, calibration, antenna, TX power, channel, and fileops implementation only after shared interfaces are reconciled.
   - Confirm every callback in its fileops initializer exists with the target's exact signature.
   - Do not omit required tables or register definitions to force compilation.

7. **USB identification and configuration**
   - Add 0bda:b711 only after the driver can fully initialize and teardown.
   - Preserve existing USB IDs and all existing Realtek config entries.
   - Keep RTL8XXXU disabled until the complete code compiles and the module is explicitly selected for test. Avoid competing module binding with existing Realtek drivers.
   - Confirm whether the adapter first enumerates as a virtual CD-ROM before considering modeswitch/eject; never issue modeswitch blindly.

8. **Build, static checks, and runtime acceptance**
   - Build against the exact GKID toolchain/config and target architecture; resolve warnings/errors without weakening unrelated configs.
   - Compare generated config and module list before/after.
   - Test module load/unload, USB bind, firmware request, interface creation, scan, association, traffic, suspend/resume if supported, and repeated unplug/replug.
   - Verify existing Wi-Fi and other device drivers remain functional.
   - Only after passing, create a separate test ZIP; never overwrite the original release ZIP.

## Current confirmed status

- Only audit documentation exists on this branch; no driver source or kernel config has been modified.
- `CONFIG_RTL8XXXU` has not been enabled in the user's builder config.
- No compile, runtime test, or flashable ZIP has been produced.
- GitHub source editing alone cannot prove a kernel build. A real build must run in the user's compatible Ubuntu/NetHunter build environment or another verified Linux build runner.

## Decision gate

**Do not begin a source patch by appending USB ID 0xb711 or copying rtl8xxxu_8710b.c alone.** First identify and validate a complete 6.1-compatible rtl8xxxu base, then port the RTL8710BU delta in dependency order. This is the lowest-risk route for preserving all existing drivers.
